# Классификация нефтегазовых месторождений

## О проекте

Проект посвящён задаче бинарной классификации нефтегазовых месторождений по геолого-промысловым и категориальным признакам.

Цель — предсказать тип месторождения:

- `ONSHORE`
- `OFFSHORE`

Изначально задача была решена в формате Kaggle-ноутбука, после чего проект был оформлен в воспроизводимый ML-pipeline с отдельными скриптами для обучения, предсказания и анализа результатов.

## Задача

Построить модель машинного обучения, которая по набору признаков определяет тип месторождения.

На этапе EDA было обнаружено, что смешанный класс `ONSHORE-OFFSHORE` представлен небольшим числом наблюдений. В текущей версии проекта он исключён из моделирования, поэтому итоговая постановка — бинарная классификация `ONSHORE` vs `OFFSHORE`.

## Данные

В проекте используются два файла:

- `train_oil.csv` — размеченные данные для обучения и оценки модели
- `oil_test.csv` — тестовый набор без таргета, для получения финальных предсказаний

Файлы находятся в директории:

- `data/raw/`

## Что сделано в проекте

### 1. Исследовательский анализ данных

В ноутбуке выполнены:

- обзор структуры датасета;
- анализ типов признаков;
- анализ пропусков;
- анализ распределения целевой переменной;
- анализ категориальных признаков, включая признаки с высокой кардинальностью;
- проверка связи признаков с целевой переменной.

### 2. Подготовка данных

Предобработка вынесена в `src/data_preprocessing.py` и реализована через `ColumnTransformer`.

Для числовых признаков используются:

- заполнение пропусков медианой;
- стандартизация.

Для категориальных признаков используются:

- заполнение пропусков значением `Unknown`;
- `OneHotEncoder(handle_unknown="ignore")`.

Все преобразования обучаются только внутри pipeline, поэтому preprocessing не использует информацию из holdout-выборки.

### 3. Сравнение моделей

На тренировочной части данных сравниваются следующие алгоритмы:

- `DummyClassifier`
- `LogisticRegression`
- `KNeighborsClassifier`
- `DecisionTreeClassifier`

Оценка выполняется с помощью `StratifiedKFold` и `cross_validate`.

Основная метрика:
- `balanced_accuracy`

Дополнительные метрики:
- `f1_macro`
- `accuracy`

Такой набор метрик выбран потому, что классы распределены не полностью равномерно, и важно отдельно контролировать качество по обоим классам.

### 4. Схема обучения и оценки

Логика обучения состоит из двух этапов:

1. На тренировочной части выполняется кросс-валидация и выбирается лучшая модель.
2. Выбранная конфигурация оценивается на holdout-выборке, которая не используется при выборе алгоритма.

После этого модель переобучается на всём очищенном размеченном датасете и сохраняется в файл:

- `models/best_model.pkl`

Таким образом, holdout используется для независимой финальной проверки, а сохранённая модель обучается на максимально доступном объёме размеченных данных.

### 5. Inference и анализ результатов

Для получения предсказаний на `oil_test.csv` используется отдельный скрипт:

- `src/predict.py`

Для анализа качества и интерпретации формируются артефакты:

- `outputs/figures/confusion_matrix.png`
- `outputs/figures/logreg_coefficients.png`

Confusion matrix строится по holdout-предсказаниям, сохранённым после обучения.  
График коэффициентов используется для интерпретации итоговой модели `LogisticRegression`.

## Результаты

По результатам кросс-валидации лучшей моделью стала `LogisticRegression`.

Качество на cross-validation:
- `balanced_accuracy`: `0.824 ± 0.030`

Качество на holdout-выборке:
- `balanced_accuracy`: `0.807`
- `f1_macro`: `0.813`
- `accuracy`: `0.852`

Дополнительно модель была применена к тестовому набору `oil_test.csv`, для которого был сформирован submission-файл в формате Kaggle.

Public score на Kaggle:
- `0.86432` по метрике F1

## Интерпретация результатов

Сравнение cross-validation и holdout показывает умеренное снижение качества на отложенной выборке без явных признаков утечки данных.

По holdout confusion matrix видно, что модель лучше распознаёт класс `ONSHORE`, чем `OFFSHORE`. Поэтому в проекте основная оценка опирается не только на `accuracy`, но и на `balanced_accuracy`.

Отдельно была проверена гипотеза о влиянии высококардинальных признаков. Их удаление немного снизило качество модели, что указывает на наличие полезного сигнала, но такой результат требует аккуратной интерпретации: часть прироста может быть связана с особенностями конкретных категорий и ограниченным объёмом выборки.

Коэффициенты `LogisticRegression` используются как инструмент общей интерпретации модели. Их не следует трактовать как причинную связь или как окончательный рейтинг важности признаков.

## Ограничения проекта

У текущей версии решения есть несколько ограничений:

- после исключения редкого класса обучающая выборка остаётся сравнительно небольшой;
- оценка на одном holdout чувствительна к конкретному разбиению;
- часть категориальных признаков имеет высокую кардинальность;
- качество по классу `OFFSHORE` оценивается по относительно небольшому числу наблюдений;
- в проекте не проводился глубокий подбор гиперпараметров и не сравнивались более сложные способы кодирования категориальных признаков.

## Как запустить

1. Клонировать репозиторий

```bash
git clone <repo_url>
cd oil-field-classification
```

2. Установить зависимости

```bash
pip install -r requirements.txt
```

3. Запустить полный pipeline

Основной способ запуска:
```bash
make all
```
Если в системе интерпретатор вызывается как python3, можно использовать:
```bash
make PYTHON=python3 all
```

4. Запуск по этапам

Обучение модели:
```bash
make train
```

Формирование submission:
```bash
make predict
```

Построение артефактов анализа:
```bash
make analyze
```

Если требуется, можно переопределить интерпретатор:
```bash
make PYTHON=python3 train
make PYTHON=python3 predict
make PYTHON=python3 analyze
```
